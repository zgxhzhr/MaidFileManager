# Maid File Manager

**车万女仆档案（迁移）管理器**（Maid File Manager）是一款 [Touhou Little Maid](https://github.com/TartaricAcid/TouhouLittleMaid)（车万女仆）的附属模组，核心功能只有一个：把你的女仆打包带走。

无论是换整合包重新开始，还是把单机养成的女仆带到服务器里，本模组都能让女仆数据在 1.20 / 1.20.1 / 1.21 / 1.21.1 之间自由迁移，并同时支持 Forge、NeoForge 与 Fabric 三大加载器。

> Fabric 版本基于社区非官方移植的 TLM，非车万女仆本体官方支持，如遇问题请先确认是否为移植版自身原因。

配套图文教程：<https://www.mcmod.cn/post/6715.html>

## 功能特性

- **一键导出/导入**：游戏内按 U 键唤出面板（可在「选项 → 控制设置 → 女仆文件管理」中改键），勾选女仆即可导出为 `.maid` 文件，勾选文件即可导入还原
- **批量操作**：支持同时选中多个女仆或文件，一键批量导出/导入
- **跨版本搬运**：1.20 ↔ 1.20.1 ↔ 1.21 ↔ 1.21.1 导出的 `.maid` 文件互相兼容，导入时自动完成数据迁移
- **药水效果跨版本迁移**：导出时同时保存原版 NBT（active_effects）与跨版本标准化（normalized）双份数据，导入时按目标版本自动恢复
- **万法皆通常驻 buff 保护**：禁药水模式下，按「效果 ID 命中白名单（11 种万法皆通结构女仆固定的永久常驻效果）+ Duration=-1」双条件判定，将常驻效果写入持久化标签保留，再次导出可恢复；不依赖女仆实体身份判定
- **饰品导入**：默认携带，可关闭；仅恢复车万女仆本体与万法皆通两个命名空间的饰品，一律全新生成（无附魔、不继承耐久），目标世界缺注册物品时安全跳过
- **进度导入**：默认携带，可配置是否还原女仆成就进度
- **导入后删除源文件**：导入 Tab 提供「导入后删除文件」开关（默认关闭），仅删除服务端确认生成成功的那批，失败文件原样保留
- **AI 对话数据迁移**：AI 人设（CustomSetting）、聊天历史（MaidHistoryChat，最多 512 条）、压缩摘要（MaidHistorySummary）、Token 用量跨版本完整迁移
- **安全防护**：导出时不保留背包与主副手物品，防止利用导出机制刷取物品
- **防重复导入**：同一位女仆无法重复导入。导入实体 UUID 按「源女仆 UUID + 导入玩家 UUID」确定性生成（无任何额外存储）——同一玩家重复导入同一文件会命中已存在的副本（全维度检测，已加载实体与未加载区块均能识别），被拦截时给出明确原因；不同玩家各自导入同一文件互不冲突，原女仆死亡、被移除或跨存档导入均不受影响。女仆被收入魂符后无法借此刷取：重复导入的副本与魂符内女仆同 UUID，魂符将无法再放出
- **服务端统一导出**：仅 OP（权限等级 2）可用，按玩家分组导出到服务端 `maid_exports/<玩家名>/`；只写文件、永不移除女仆；需每位玩家本人同意（默认不同意）
- **服务端配置同步**：联机宿主集中管控四项开关，客户端进服自动同步
- **附属数据迁移 SPI**：对外提供统一迁移接口（`MaidMigrationProvider`），附属模组可自行注册，把不在女仆实体 NBT 上的数据（独立 SavedData / Capability / 玩家持久化数据 / 外部存储等）随 `.maid` 一起迁移；附属未加载时自动跳过、不报错。详见下文「附属模组接入」
- **属性迁移公平可信**：血量 / 攻击力基础值导入时无条件回归车万女仆按好感等级（含渡劫）计算的白板值，全局生物血量倍率类模组直接抬高的数值不随女仆跨存档迁移，保证联机导入公平；附属模组通过饰品 / 词条修饰符提供的合法加成在女仆入世界后自动恢复，满血女仆导入后不再掉血
- **无残留**：卸载模组不影响已导入的女仆

## 安装

1. 安装对应版本的 Forge / NeoForge / Fabric（Fabric 还需 Fabric API）
2. 安装 Touhou Little Maid（车万女仆）模组作为前置；Fabric 用户请安装社区非官方移植版 TLM
3. 将本模组 JAR 放入 `.minecraft/mods` 文件夹
4. 启动游戏

## 使用方法

游戏目录（`.minecraft` 或整合包实例目录，与 `mods` 平级）下两个文件夹：

| 文件夹 | 用途 |
|---|---|
| `maid_exports/` | 导出结果，按玩家名分子文件夹 `maid_exports/<玩家名>/` |
| `maid_imports/` | 导入来源，把要导入的 `.maid` 文件放这里（没有可手动新建） |

1. 按 U 打开面板，在「导出」Tab 点「刷新」（列表只显示周围 128 格内、由你驯服的女仆），勾选后点导出；默认「保留原女仆在世界」开启，导出只是备份
2. 把 `.maid` 文件从旧存档的 `maid_exports/<玩家名>/` 复制到新存档的 `maid_imports/`
3. 在「导入」Tab 点「刷新」，勾选文件后点导入；可勾选「导入后删除文件」（默认关闭）；女仆生成在玩家身边安全位置并获得全新 UUID
4. 点「打开导出文件夹」可直接打开输出目录（导入 Tab 对应打开 `maid_imports/`）

## 服务端配置

四项服务端开关**默认全部开启（true）**，由联机宿主（OP）在设置中修改，客户端进服自动同步：

| 开关 | 默认 | 关闭时效果 |
|---|---|---|
| 允许客户端导入女仆 | 开启 | 所有玩家的导入被拒绝 |
| 导入时允许携带饰品 | 开启 | 饰品被丢弃 |
| 导入时允许携带进度 | 开启 | 进度数据不写入 |
| 导入时允许药水效果 | 开启 | 非白名单药水被丢弃；万法皆通 11 种常驻效果仍写入持久化标签中转保留 |

玩家侧开关「允许服务端统一导出你的女仆」**默认不同意（false）**，需玩家本人开启后，OP 才能在统一导出中导出该玩家的女仆。

## 服务端统一导出（仅 OP）

- **GUI**：导出 Tab 点「统一导出」进入统一导出模式（按钮变为「返回单独导出」），列表按玩家分组显示「▼ 玩家名（N 只女仆）」，未同意的玩家标注 [未同意导出]；提交后文件保存到服务端 `maid_exports/<玩家名>/`
- **命令**：`/maidfile exportall` 一键导出所有已同意玩家的女仆（命令搜索半径 256 格；GUI 浏览列表搜索半径 128 格）
- 实体查找采用「直接取实体 → 128 格 AABB → 全维度 AABB」三级查找防漏
- **范围限制**：只能导出每位玩家周围加载范围内、由其本人驯服的女仆；未加载区块、魂符/相片/胶卷等容器内的女仆无法覆盖。换服或灾备前请通知玩家把女仆带到身边

## 数据保留情况

| 数据 | 结果 |
|---|---|
| 主人驯服关系 | 保留（找不到原主人时生成为未驯服，用蛋糕重新驯服即可） |
| 名字 / 模型 | 保留（目标端缺模型时显示为博丽灵梦） |
| 血量 | 回归白板值。基础值无条件重置为车万女仆按好感等级计算的白板血量（满好感 80、渡劫 100），不保留源存档基础值——全局生物血量倍率类模组直接抬高的基础值不随女仆迁移，保证联机导入公平；持久修饰符迁移时随属性标签整体清除，附属合法的饰品 / 词条修饰符在女仆入世界 tick 后自动附加 |
| 攻击力 | 回归白板值。基础值无条件重置为车万女仆按好感等级计算的白板攻击力；附属通过饰品 / 词条修饰符提供的加成入世界后自动恢复 |
| AI 对话数据 | 保留（人设、聊天历史、摘要、Token 用量） |
| 饰品 / 药水效果 / 进度 | 默认保留，可分别关闭 |
| 背包与主副手物品 | 不保留（导出前请先取回） |
| 原 UUID / 着火、坠落等运行时状态 | 不保留（导入时生成新 UUID） |

## 附属模组接入（SPI）

本模组不针对任何具体附属做硬编码适配，而是对外提供一套统一迁移接口。附属模组如果有**挂在女仆身上、但不在女仆实体 NBT 内**的数据（独立 `SavedData`、Forge Capability、玩家持久化数据、外部数据库等，通常通过女仆 UUID 关联），可以自行接入，让这部分数据随 `.maid` 一起迁移。

接入只需两步：

1. 实现 `io.github.zgxhzhr.maidfm.spi.MaidMigrationProvider`，共四个方法——`getId()`（唯一标识，建议 `你的modid:数据名`）、`getDependencyModId()`（依赖的 modid，用于软依赖检测）、`export(EntityMaid)`（导出该女仆的附属数据为 `CompoundTag`，无数据返回 `null`）、`importData(EntityMaid, CompoundTag)`（导入时把数据写回你的存储系统）。
2. 在你的模组初始化阶段调用一行 `MaidMigrationRegistry.register(new XxxProvider());`。

设计约束与保障：

- 接口参数只依赖女仆实体与 NBT，不引入任何具体附属的类型，编译时 `compileOnly` 依赖本模组即可
- 数据存在哪里完全由附属自己决定，本模组只负责在导出 / 导入时调用并搬运 `CompoundTag`
- 附属模组未加载时对应数据段自动跳过，不报错；附属 `export` / `importData` 抛异常会被隔离，不影响女仆主体和其他附属
- 导入后女仆会获得新 UUID，附属需以 `maid.getUUID()` 为准写回，不要使用导出时的旧 UUID
- `.maid` 文件 v5 起新增 `extras` 复合标签承载附属数据；旧版无此标签的文件正常导入（向后兼容），新版文件在旧版本模组中导入时该标签被忽略

> 已经把数据写在女仆实体 NBT（含 `getPersistentData()` 与 Forge Capability 随存档序列化的字段）里的附属**无需接入**——本模组用 `EntityMaid#saveWithoutId` 导出完整女仆 NBT，这部分数据会自动随女仆迁移。

## 版本历史

### v1.4.0
- 新增：附属模组统一迁移接口 SPI（`MaidMigrationProvider` + `MaidMigrationRegistry`），附属可自行注册导出 / 导入自身数据；`.maid` 文件格式升级到 v5，新增 `extras` 字段（旧 v4 文件正常导入，向后兼容）
- 新增：同一女仆重复导入拦截。导入实体 UUID 不再随机，而由「源女仆 UUID + 导入玩家 UUID」经 v3 名字 UUID 确定性派生（纯函数，无任何额外存储，不会随导入次数增长）：同一玩家重复导入同一文件时目标 UUID 恒定，导入前在全维度已加载实体与 `MaidWorldData` 未加载索引中检测该 UUID，命中即拒绝并提示具体原因；不同玩家导入同一文件因玩家 UUID 参与派生而互不冲突（多人服分享文件不受影响）；原女仆死亡 / 被移除 / 跨存档导入不受影响。女仆被收入魂符（实体离线、索引不可查）时重复导入虽会成功，但魂符内女仆与副本同 UUID 无法再放出，不能借此刷取。`.maid` 新增 `source_maid_uuid` 字段，旧文件从实体根 NBT 的 UUID 键兜底解析
- 改进：血量 / 攻击力基础值导入时无条件回归车万女仆按好感等级（含渡劫）计算的白板值，不再保留源存档基础值——全局生物血量倍率类模组（直接改基础值或写持久修饰符）抬升的数值不再随女仆跨存档迁移，保证联机导入公平；附属通过饰品 / 词条修饰符提供的合法加成在女仆入世界后自动恢复
- 修复：满血且带饰品 / 词条血量修饰符的女仆导入后掉血。原因是固定延迟一次校准无法保证晚于所有附属附加修饰符；改为在入世界后的有界窗口（约 1 秒）内逐 tick 按当前最大血量校准，可追上任意时刻附加的修饰符
- 重构：Java 包名由 `com.example.maid_file_manager` 迁移为 `io.github.zgxhzhr.maidfm`（MOD ID 仍为 `maid_file_manager`，不影响 `.maid` 文件与存档）
